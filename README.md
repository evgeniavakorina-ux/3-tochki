# «3 точки» — автоматический расчёт Солнца, Луны и Асцендента

Статичный сайт для GitHub Pages. Сервер, регистрация и API-ключи не нужны. Данные рождения не сохраняются: они живут только в памяти открытой страницы.

## Файлы
- `index.html` — интерактив (экран «Данные рождения» + прежний ручной выбор и интерпретации).
- `astro-core.js` — расчёт: Солнце, Луна, Асцендент, дома, часовые пояса.
- `vendor/` — библиотеки (подключены локально, CDN не нужен).
- `tests/` — тесты и сверка со Swiss Ephemeris.

## Настройки (как в «Хроносе»)
В `astro-core.js`, объект `SETTINGS`:
- основная система домов — Плацидус;
- с 61°45′ с. ш. включительно (`61.75`) — равнодомная от Асцендента;
- Порфирий не используется никогда: если Плацидус не считается, это ошибка, а не подмена;
- южные широты — пока зеркальное правило (`southernRule: 'mirror'`), ждёт согласования.

## Точность (сверка со Swiss Ephemeris 2.10.03, 20 000 случайных карт, 1900–2030 гг., широты −60°…+70°)
- Солнце: расхождение не больше 2.5″.
- Луна: не больше 5.8″.
- Асцендент и куспиды Плацидуса: не больше 2.1″.
- Расхождений по знакам: 0.

За полярным кругом Асцендент приведён к соглашению Swiss Ephemeris (Асцендент в пределах 180° после MC). **Проверить по «Хроносу»** на Мурманске, Норильске и Воркуте.

## Тесты
```
npm install
npm test
```
Сверка со Swiss Ephemeris: `pip install pyswisseph`, `node tests/gen-samples.js`, `python3 tests/compare-swisseph.py`.

## Что проверить по «Хроносу» до запуска
1. Контрольные карты: знаки + смещение от UTC.
2. Роды до 1970 года и регионы, которые меняли часовой пояс отдельно. tzdb надёжна в основном с 1970-го. Если расхождение найдётся, у пользователя есть поле ручного смещения от UTC.
3. Города возле 61°45′: координаты OpenStreetMap и атласа «Хроноса» могут отличаться на минуты, а это меняет систему домов.
4. Асцендент севернее 66°33′.

## Обновление
- tzdb: обновить `moment-timezone`, скопировать `builds/moment-timezone-with-data.min.js` в `vendor/`.
- Порог и системы домов: `SETTINGS` в `astro-core.js`.
